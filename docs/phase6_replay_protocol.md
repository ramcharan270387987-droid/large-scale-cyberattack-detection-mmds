# Phase 6 historical replay protocol

Phase 6 v1 uses the Phase 2 Parquet version 1 and the chronological B outputs of Phase 4 and Phase 5 version 2. Validate the receipts and per-file model hashes before inference. Use the registered 18 finite-or-null numeric inputs in the original order. Preserve provenance and evaluation fields as a nested audit record kept outside all model inputs. Random Forest and Logistic Regression use the group-sample saved pipelines with inclusive score threshold 0.5. The duration baseline uses the frozen benign-training median and predicts benign for missing duration. K-Means uses the saved historical pipeline, its 12 centroids and its strict reference P99 distance rule.

The B design keeps the six observed days from February 14 through 22 as the reference, February 23 and 28 as validation, and March 1–2 for later evaluation. Apply the existing earliest-split predictor-key rule and reconcile the 909,956 removed rows and binary and family support against the Phase 4/5 outputs. Replay every retained row. Preserve the original timestamp, parsed timestamp without timezone, trusted capture day, eligibility, source name and fingerprints. Stage one Parquet object per occupied three-hour capture window, plus a capture-day-only object for ineligible timestamps where present. Assign a monotone integer chunk sequence by capture day and window with capture-day-only chunks last. Sort the constituents of a chunk by wall-clock time and deterministic content and predictor digests. Identical provenance and content ties are interchangeable. Physical Spark row order has no analytical role.

Write stage files before starting the available-now query. Publish them to a local read directory with unique ascending modification times that encode the declared sequence. Parse an explicit schema with Spark Structured Streaming and ingest one file per trigger. Check the actual chunk sequence in each callback against the source manifest. The checkpoint and aggregate sink use the same source manifest, including across restart. The sink writes one atomic aggregate document per Spark batch ID and validates its sequence on retry. A deliberate exception after the second batch's durable publish and before its commit tests the recovery boundary. The next query reuses the checkpoint and verifies the unchanged document before committing that batch. Temporary writes are ignored. No exactly-once guarantee extends to other storage systems or external alert delivery. Processing timestamps and latency measure the experiment rather than the original capture.

Freeze reference histograms and observed baseline performance using only the completed training-capture aggregates. Never update references on validation or test rows. Use the Phase 5 B occupancy vector to cross-check reference cluster counts. Monitor six predeclared raw features using fixed physical-unit bins with explicit missing and overflow bins. Score bins are 2,048 equal-width intervals across [0, 1], with score 1 in the final bin. Cluster IDs form a categorical histogram. Jensen–Shannon divergence uses base 2 with no smoothing. Zero-count terms contribute zero. Novelty rates use the saved strict threshold. Report mean distance and an upper bin bound for the P95 distance, with the overflow tail explicitly unsupported. Retrospective score histograms record PR-AUC only when both classes are observed. The descriptive support is recorded row count, which includes dependent and repeated flows.

Alert on JS above 0.10, novelty rate more than 1.5 percentage points above training, or observed Random Forest recall more than 20 percentage points below training. Minimum support is 10,000 rows, and recall warnings require at least 100 rows per class in both populations. Validation/test use fixed thresholds. Severity is high at twice the configured difference threshold and warning otherwise. Reveal labels retrospectively through the aggregate callback after frozen scoring. Keep unsupervised distribution alarms independent of labels. These alerts describe historical replay and can reflect shifts in traffic mix, model scores or observed performance. Concept drift requires separate identification evidence.

Use a four-worker Spark 4.3.0 CPU session with an 8 GiB heap, 48 shuffle partitions, and at most 90 chunks or 8 GiB of staged inputs. Measure elapsed wall time, JVM peak resident memory, file bytes, checkpoint bytes and per-batch scoring and aggregate timings. Compare one and two files per trigger on the first four eligible chunks using separate checkpoints on the same machine. The comparison is bounded and order effects may affect throughput. Omit offline refresh in this phase. The two final captures already define the frozen holdout, and there is no independently verified retrospective label-availability timeline for a fair operational refresh claim.
